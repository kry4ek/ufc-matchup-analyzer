# v0.6 records and behavior

Initial comparison schema 1 has `quick_comparison=true`, `result_state=initial`, stable fighter IDs, the calculation request/context fingerprint, generation time, history cutoff, effective training cutoff, eligible recorded bout counts, profiles from the installed snapshot, and frozen last-five history. It has no probabilities or model summary. Cancellation/failure preserves a clearly partial report; partial reports never enter completed history. Draws/NCs count as recorded bouts and are distinct from an engine's decisive-fight denominator.

Request-time full content validation precedes initial evidence. Exact saved-result reuse is checked first. One catalog resolves both identities and supplies dated coverage, avoiding three repeated catalog loads. The worker retains its operation lock across all stages. `initial_ready` and `comparison_ready` events carry the worker's request/job identity; the GUI keeps older reports visible when selected during work. The current full result protocol already supports large result records; initial records remain small and use that channel, not progress counters.

Visual evidence schema 1 freezes paired metric values, definition IDs, semantic versions, units, support limits, and engine-derived pre-bout Elo points. Percent bars use 0–100%; other rates share a zero-based scale per metric. Missing values stay unavailable. Legacy rate attempt denominators are explicitly unavailable and eligible fight counts are not described as rate support. Men use stored engine decisive-bout pre-Elo rows; women use `hist_stats` produced by the existing live preparation. Selected-date/later points are excluded. Division columns refer to the division of the recorded bout; they are not a continuous selected-division series. Same-day order is deterministic, without claiming actual bout chronology. Older records may render their own frozen metrics but do not acquire current-source Elo histories.

History schema 1 and its 50-entry/50-MiB budget are retained. Imports accept bounded, integrity-checked JSON only, preserve original records/context/timestamps, and never deserialize prior calculation artifacts. An import preview captures source entries and fingerprints, capped at 50 MiB of source entry content and 200 files. Apply rechecks source/target state and installs that capture. Exact entries deduplicate; different-content ID collisions are skipped. Existing target records are never pruned to make space. Entries exceeding default available capacity are listed as over budget; users can select a different captured subset that fits. Apply checks both source and serialized destination sizes. Current history-storage settings survive import. Validated text/window/collapse preferences and remembered selections are offered; fighter names must resolve unambiguously in the current catalog, with obsolete names cleared. Machine-specific export paths are excluded. Imported preferences are applied to live controls so normal app closure retains them; undo preserves subsequent changes.

Import commit journals describe only owned destination files and preference before/after values. Complete staged files are linked exclusively into history; no target file is overwritten. Interrupted imports roll back matching owned files on startup. Undo retains changed files and reports conflicts. Original folders remain read-only. The latest import can be undone. Read-only files, source changes, conflicts, malformed/newer records, low disk space and cancellation are explicit outcomes.

Validation artifact schema 1 is a dated research result with model/code/data hashes, protocol version, complete planned/evaluated/excluded/failed/remaining counts, frozen holdout metrics, calibration bins, event-cluster uncertainty when supported, and audit limitations. Its content hash is checked when reading. The app compares installed data/engine hashes without running model fitting. No aggregate metric becomes a per-fight guarantee. A failed internal methodology audit must be visible and prevents a clean validated-model claim.
